# 公众号回归验证长文

> 用途：把本文全文复制到 markdown-to-wechat 网页端或桌面端，分别用 `秋河` 与 `朱简` 主题渲染后，粘贴到微信公众号后台，逐项核对下表元素在 PC 端与手机端的真实表现。
>
> 本文覆盖渲染器声明支持的全部元素。任何一项在公众号后台塌陷、丢样式或错位，都应转成最小 Markdown fixture 与一条回归测试。
>
> 验证结论请记录到 `90-Agent档案/qc/真实公众号验证-YYYY-MM.md`。

::: lead
这是一段 lead 语义指令，用于文章导语。它应当在公众号中保持与正文区分的视觉层级，不丢失缩进、字号或颜色关系。
:::

## 一、标题层级（H1–H4）

# H1 一级标题

## H2 二级标题

### H3 三级标题

#### H4 四级标题

**核对点**：四级标题是否都保留了主题定义的字号递减、颜色与装饰关系。公众号后台是否会吞掉 H1 或把某一级重置为默认样式。

## 二、行内样式与强调

正文段落中含**加粗文本**、*斜体文本*、~~删除线~~、`行内代码`，以及==重点标记==。

中英文混排时的间距处理：Markdown 渲染器使用 TypeScript 编写，输出 HTML 供 WeChat 使用。

长英文单词与 URL 的折行表现：`supercalifragilisticexpialidocious` 与 `https://ansel-poiesis.github.io/markdown-to-wechat/`。

**核对点**：加粗颜色是否跟随主题强调色；行内代码是否有底色与等宽字体；重点标记是否被公众号过滤掉；中英文间距是否仍然生效。

### 复杂表格（多列、长内容、对齐）

| 组件 | 主题跟随 | 独立变体 | 微信后台表现 | 备注说明 |
| --- | :--- | :---: | ---: | --- |
| 封面 | 是 | 编辑部、朱印、极简 | 待验证 | 长内容单元格在窄屏是否溢出 |
| 章节 | 是 | 编号、分割线、标签 | 待验证 | — |
| 引用 | 是 | 拉引、面板、边线 | 待验证 | 嵌套层级较多时表现 |

## 六、代码块

### 短代码块

```ts
export const version = '2.0.1'
```

### 长代码块（含缩进、多语言关键字、特殊字符）

```ts
import { createServer } from 'node:http'
import { existsSync, readFileSync } from 'node:fs'

interface RenderOptions {
  theme: string
  lineNumbers?: boolean
}

// 行注释：测试注释着色与中英文混排
export function render(markdown: string, options: RenderOptions): string {
  const lines = markdown.split('\n')
  const output: string[] = []

  for (let index = 0; index < lines.length; index += 1) {
    const line = lines[index] ?? ''
    if (!line.trim()) {
      output.push('')
      continue
    }
    if (line.startsWith('```')) {
      output.push(`<pre>${escapeHtml(line)}</pre>`)
      continue
    }
    output.push(`<p style="margin:0">${escapeHtml(line)}</p>`)
  }

  return output.join('\n')
}

function escapeHtml(text: string): string {
  return text
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
}
```

**核对点**：代码块是否保留等宽字体、换行与缩进；语法着色是否幸存；`<`、`>`、`&`、`"` 等特殊字符是否被正确转义而非显示为实体名；长代码块在手机端是否溢出或可横向滚动。

> [!note]
> 未闭合代码围栏的边界测试已移至本文**最末尾的附录**。原因：按 Markdown 规范，未闭合围栏会延伸到文档结束，若放在中间会把它之后的全部章节吞成纯文本，导致图片、外链脚注等章节的验证结论失效。已于 2026-09-07 实测确认此行为。

## 附录：未闭合代码围栏边界测试（必须保持在文档最末尾）

> [!important]
> 本附录以下方那个**故意不闭合**的代码围栏结束全文。它必须永远是文档最后的内容。若把任何章节移到它之后，那些章节会被吞成纯文本，验证结论随之失效。
>
> 2026-09-07 已实测：围栏置于第六章时，第七至第十章的图片、`<figure>`、图注、外链脚注编号全部丢失，`<img>`/`<sup>` 计数为 0。移至末尾后各章节恢复正常渲染。这一行为本身值得作为回归用例保留。
