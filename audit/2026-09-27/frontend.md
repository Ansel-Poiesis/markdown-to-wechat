# 前端可靠性审计与修复

日期：2026-09-27。源码基线：`origin/main@1182575`；工作分支由主审计任务管理。本文只覆盖前端交互、浏览器本地存储和可访问性，渲染器、Electron、依赖、视觉截图与总体发布结论分别见本轮其他证据。

## 判断

工作台已有清晰的本地优先定位和集中式主题能力，但基线不能判为“准确无误”：存在未经用户操作修改原稿、草稿故障后恢复丢失、复制失败却报成功、平板宽度裁切等实际问题。本轮已修复下述具体缺陷，完成定向回归。通过这些测试不等于真实微信公众号粘贴验收，也不等于无限输入、任意浏览器或多窗口并发全部成立。

## 存储恢复协议

- `wechat-md-drafts` 继续作为草稿归档，`wechat-md-active-draft-id` 为活动稿指针。
- `wechat-md-workspace-backup` 是新工作区备份：`{ version: 1, draftId, content, updatedAt }`，正文和身份通过一次 `localStorage.setItem` 写入。
- `wechat-md-draft` 旧字符串只用于无新备份时的迁移读取，本轮不清空或覆盖它。
- 新备份比同 ID 的归档更新时间更新且内容不同时，恢复对应稿。活动指针不同也不会把恢复内容写进另一篇稿件。备份对应的新稿从未成功进入归档时，创建独立的“恢复：…”稿件。
- 归档和 recovery JSON 损坏时，保留原值并暂停相关覆盖。恢复方式是先导出/复制当前编辑原文，另行备份浏览器同源存储中的原值，再修复数据或权限后刷新；程序不自动清空存储。
- 存储完全拒绝写入时，本页只能保留内存中的修改，必须先另行保存再离开。浏览器关闭提示属于保护措施，不是持久化成功证据。

## 剩余优化计划与验收边界

1. **P2：多窗口并发与存储容量。** 当前没有跨标签页锁、冲突合并或历史修订。去掉旧 useStorage 的自动跨页原稿替换避免无提示内容串页，但仍是最后一次写入覆盖归档；下一阶段引入 IndexedDB 单稿记录/修订、冲突提示和源 Markdown 备份导入导出。先用两个标签页同时编辑不同稿与同稿的回归固定行为，不能宣称多端同步。
2. **P2：持续编辑性能。** 本轮限制危险渲染输入并限制命名扫描；全量 localStorage 归档序列化和主线程渲染仍随内容/稿数增长。下一阶段以真实 20/100/500 篇稿和连续输入计量阻塞，再决定按稿保存、防抖+退出 flush 或 Worker；不能以一次渲染耗时代替交互帧率。
3. **P2：视觉可读性。** 保持现有克制的浅灰/绿色工作台方向。主审计在最终构建将浅色 tertiary 从 `#8c9994` 调为 `#65736d`，保存状态从 10px 调为 11px；浏览器已确认 computed style，白底对比由约 2.96:1 改善到 4.97:1。仍需统一测浅/深两套其他实际背景、小字与触控目标；本轮没有更换主题风格，也未宣称全站通过可访问性认证。
4. **专项验收：** 真实微信后台富文本粘贴、桌面端剪贴板与下载、iOS safe-area/系统返回、屏幕阅读器、PNG 真实透明像素、GIF 原速动画、多图拖放及持续编辑时取消结果，仍需对应真实环境验证。单测 MIME 和模拟 DOM 不等于这些人工验收。

本轮前端结论为 **patch candidate**，不构成对外发布或“实现绝对无误”的承诺。
